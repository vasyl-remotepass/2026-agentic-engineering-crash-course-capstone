# tt — правила для агента

## Джерело правди

- Поведінка описана в [spec.md](spec.md). Якщо задача вимагає поведінки, якої там немає або яка
  суперечить spec, **спочатку зупинись і спитай**. Після мого «так» правиш spec (розділ «Зміни
  специфікації», з причиною), потім код.

## Код

- Python 3, **лише stdlib**. Жодних `pip install` і нових залежностей.
- Два файли: `tt.py` (весь код) і `test_tt.py` (усі тести). Нових модулів не створюй.
- Поточний час — параметр `now`. `datetime.now()` викликається лише в `main()`.
- Повідомлення CLI — англійською, як у spec. Документація — українською.

## Перевірка

- Одна команда, з цієї теки: `python3 -m unittest -v`.
- Задача не зроблена, поки вона не зелена. У звіті — вивід, а не «тести проходять».
- **Не змінюй тест, щоб він пройшов.** Якщо тест здається неправильним — зупинись і скажи, який і чому.

## Межі

- Тести і будь-які прогони — лише з `TT_FILE` у тимчасовій теці. Мій `~/.tt.json` не чіпати.
- Файли поза `submissions/vasyl-dmytruk/` не змінювати (`README.md`, `RUBRIC.md`, `.github/` — курсові).
- Без `git push`, PR і будь-яких зовнішніх дій.
- Файли харнесу (`AGENTS.md`, `CLAUDE.md`, `.claude/`, `loop.sh`) змінює лише людина або агент з її явного «так».
